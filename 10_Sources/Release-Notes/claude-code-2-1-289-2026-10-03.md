# Claude Code 2.1.289

> Claude Code, 2.1.289, 3 October 2026.

## Summary

Version 2.1.289 is dominated by permission and plugin hardening. Several fixes make Bash and Read deny and ask rules hold in cases where they were previously missed: a nested part of a compound command, a command behind an environment variable prefix under sandbox auto-allow, a bare variable assignment before the command, and files reached through a symlink in the IDE. It also fixes a user-installed plugin rewriting the descriptions of an organisation-managed MCP server's sign-in tools, adds `agent.spawn` for teammates and a single agent id across plugin hook events, and makes many mod and plugin rendering fixes. The changelog was read from the repository CHANGELOG.md; the date comes from the GitHub release record.

## New Capabilities

- `agent.spawn` for teammates, one agent id across plugin hook events, and idle and waiting states in `$.agent.list()`.
- `claude plugin validate` now handles a folder that also holds a marketplace manifest, and no longer fails an Anthropic marketplace's own plugin.
- Faster opening of large files in a plugin code pane.
- Clearer error lines when a mod's band or pane fails to draw, naming the mod.

## Deprecated Features

- None stated in this version.

## Migration Notes

- The VS Code change to `claude auth status` made in 2.1.288, which may have caused more frequent sign-outs, was reverted.
- Plugins that used borders, links or regions that previously crashed the interface now degrade rather than end the session.

## Engineering Implications

- Permissions: a deny or ask rule on a nested part of a compound shell command now holds over a user-installed mod's approval on managed machines. Bash deny and ask rules are no longer skipped under sandbox auto-allow when a variable assignment or an environment variable prefix with an expanded value precedes the command. `Read` deny rules now apply to files @-mentioned, changed or selected in the IDE through a symlink. Review any rule set that relied on the old gaps.
- MCP configuration and plugins: a user-installed plugin can no longer rewrite the descriptions of an organisation-managed MCP server's sign-in tools, which closes a tool-description injection path on managed machines.
- Hooks and subagents: plugin hook events now share one agent id, which makes hook output attributable to a specific teammate or subagent.
- Headless and background sessions: supervised and background sessions no longer end when a plugin's on-screen handler throws asynchronously, and sessions no longer end with an interface error when a mod's render hook writes a bad value.
- Authentication: the `claude auth status` revert affects VS Code sign-in stability only.
- No `-p` flag or output format changes appear in this version.
