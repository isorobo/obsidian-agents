# Introducing Claude Opus 5.5

> Claude Opus 5.5, model id `claude-opus-5-5`, 22 September 2026.

## Summary

Anthropic released Claude Opus 5.5 on 22 September 2026 across the Claude Platform, AWS, Google Cloud and Microsoft Azure. The announcement cuts per-token prices and claims roughly 40 percent lower cost than Opus 5 on typical workloads, with output generated about 30 percent faster. Reported results include 66.4 percent on Terminal-Bench 4.0, 54.4 percent on FrontierCode v1.1 and 81.8 percent (partial credit) on OSWorld 2.1. The post also changes how thinking and safeguards behave.

## New Capabilities

- Price per million tokens: $4 input (was $5), $20 output (was $25), cache reads $0.20 (was $0.50), cache writes $5 (was $6.25). Fast mode is $8 input and $40 output.
- Improved prompt injection resistance across coding, tool use and computer use.
- Adaptive thinking at max effort by default.
- Preserved thinking anti-distillation safeguard for API accounts created after 31 August 2026.
- Zero data retention is available, and watermarking supports EU AI Act compliance.

## Deprecated Features

- Thinking can no longer be disabled on this model.

## Migration Notes

Anthropic points to a migration guide. Because thinking cannot be switched off, integrations that disabled it need updating. Cybersecurity tasks are routed to Opus 4.8, with verified practitioners reaching more capability through the expanded Cyber Verification Program. Biology tasks use Fable 5.1 level safeguards, and vetted organisations apply through the new Life Sciences Verification Program. The announcement does not state a context window.

## Engineering Implications

Lower cache read and write prices favour long, tool-heavy agent loops that reuse a large prefix. Always-on thinking changes latency and token budgeting for agents that previously ran with thinking off. Safeguard routing means a cyber or biology task can be served by a different model than the one requested, so agents in those domains need a fallback path. Better prompt injection resistance reduces risk in tool and computer use but is no substitute for permission controls. Models should stay behind a swappable model port with the model id as configuration.
