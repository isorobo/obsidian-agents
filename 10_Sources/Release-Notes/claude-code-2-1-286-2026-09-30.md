# Claude Code 2.1.286

> Claude Code, 2.1.286, 30 September 2026.

## Summary

Version 2.1.286 is mostly a fix and polish release with a few behaviour changes that matter to automation. `--bare` now connects only the MCP servers named on the command line, sends the model no system reminders and starts no background tasks. Failed API requests are retried under one limit per model call (at most 14 requests with default settings). Model fallback, resume and subagent behaviour were corrected, secret redaction in logs and transcripts was tightened, and plugin installs now refuse npm sources that are git repositories or folders. The changelog was read from the repository CHANGELOG.md; the date comes from the GitHub release record.

## New Capabilities

- Permission prompts show a count such as "2 of 5" when several requests stack up.
- Fullscreen list rows support mouse clicks on the "N more" rows.
- When a project or user skill named `verify` exists, Claude is told to run it right before committing, except for docs-only and tests-only commits.
- Send now (ctrl+enter) in a subagent's view moves the subagent's running command to the background.
- `/hooks` opens on one list of configured hooks grouped by event.

## Deprecated Features

- The browser link was removed from `/ultrareview` and `claude ultrareview` output.

## Migration Notes

- Scripts relying on `--bare` to start extra MCP servers or background tasks must name servers explicitly on the command line.
- Under `--bare`, a shell command that reaches its timeout now stops instead of moving to the background.
- Plugin installs from npm sources that are git repositories or folders are refused, and plugin dependencies install only from registry packages.

## Engineering Implications

- Headless mode: `--bare` is now a tighter, more deterministic mode (no system reminders, no background tasks, command-line MCP servers only), which suits reproducible `-p` runs.
- Cost and reliability: one retry limit covers a whole model call, capping failing calls at 14 requests by default. If the API refuses the model a default or alias resolves to, Claude Code retries once on the previous model of the same tier. Refusal and `--fallback-model` retries now run at standard speed.
- Output formats: `--output-format stream-json` and the SDK now stream the turns of a `context: fork` skill run by typing `/<skill>` as the prompt.
- Authentication: `claude auth status` reports a Console sign-in's stored API key as `api_key` rather than `claude.ai`. A revoked claude.ai login now reports "OAuth token revoked", and in `-p` mode the error starts with "Failed to authenticate". Duplicate login browsers from `gcpAuthRefresh` or `awsAuthRefresh` expiry are fixed.
- MCP: connectors no longer list no tools for up to a day after a server drops the older handshake, and credentials in MCP error messages are masked more completely.
- Subagents: foreground subagents regain the task-tracking tools, worktree-isolated subagents no longer load CLAUDE.md twice, and `/compact`, `/clear` and `/rewind` typed while viewing a background agent now ask which conversation they target.
- Permissions: the WebFetch error for a rate-limited domain check now tells Claude not to retry in a loop.
