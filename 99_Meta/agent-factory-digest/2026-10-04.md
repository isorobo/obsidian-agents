## By agent-factory target
### af:ADR-0001 What an agent is
- [[10_Sources/Blog/ai-agents-101-what-is-an-agent|AI Agents 101, What Is an Agent]]: defines an agent as a decide, act, observe loop run until the goal is met, and says the wrapper rather than the model separates an agent from a chatbot.
- [[10_Sources/Blog/anthropic-building-effective-agents|Building Effective Agents]]: draws the primary-source line between workflows on fixed code paths and agents where the model directs its own process and tool use.
- [[10_Sources/Blog/how-to-build-ai-agent-from-scratch|Build an Agent from Scratch (course)]]: reduces an agent to a tool-capable LLM, a tool registry and a loop, with a mandatory step cap, which tests the minimum definition.
- [[10_Sources/Blog/how-to-build-an-ai-agent-from-scratch|Build an Agent from Scratch (playbooks)]]: requires an input, output and boundary before code, a comparison point for the minimum definition.
- [[10_Sources/Books/agentic-ai-handbook-bar-2025|Agentic AI Handbook]]: defines agentic AI as goal setting, planning, self-reflection and autonomous action, a survey-level definition to compare with agent-factory's.
- [[10_Sources/Books/ai-agents-illustrated-guidebook-chawla-pachaar-2025|AI Agents Illustrated Guidebook]]: grades agency by how much control the LLM takes over program flow, a ready comparator for the agent versus LLM call boundary.
- [[10_Sources/Books/ai-agents-in-action-lanham-2025|AI Agents in Action]]: splits a single agent into five component systems and separates ingested knowledge from interaction memory.
- [[10_Sources/Books/what-is-an-agent-bommarito-2025|What Is an Agent (Bommarito)]]: gives a falsifiable minimum definition (Goal, Perception, Action) and a six-property agentic system, ruling out tool use or automation alone.
- [[40_Guides/ai-agents-course-chapter-1-fundamentals|AI Agents Course Chapter 1]]: defines an agent as brain, tools, memory and loop, a candidate minimum definition.
- [[30_Concepts/agent-vs-llm|Agent vs LLM]]: separates agent from LLM by statefulness and action, which directly answers the agent versus LLM call question.
- [[30_Concepts/the-agent-loop|The Agent Loop]]: defines the loop as read, decide, act, observe, guarded by a step budget or goal test and a human checkpoint.
- [[30_Concepts/what-is-an-ai-agent|What Is an AI Agent]]: defines an agent as a model, tools and a stateful loop, separated from a workflow by who picks each step.
- [[30_Concepts/workflow-vs-autonomous-agent|Workflow vs Autonomous Agent]]: draws the line by who holds control, code in a workflow and the model in an agent, so it tests where the agent definition ends.

### af:ADR-0003 Model port
- [[10_Sources/Blog/function-calling-how-llms-use-tools|Function Calling Explained]]: shows OpenAI, Anthropic and Gemini share one menu, order, serve cycle with differing field names, which informs the model port.
- [[10_Sources/Blog/gemma4-local-agents|Gemma 4 Local Agents]]: runs the same tool chain on a local open-weight model through Ollama, evidence on substituting models behind the port.
- [[10_Sources/Release-Notes/claude-sonnet-5-2026-06-30|Claude Sonnet 5]]: a new model id, claude-sonnet-5, with advice to test tool-use flows before switching traffic, a concrete substitution case.
- [[40_Guides/choosing-a-layer-in-the-claude-agent-stack|Choosing a Layer in the Claude Agent Stack]]: claims the Agent SDK swaps providers with one config line while Claude Code stays Anthropic only, a portability claim to check.

### af:ADR-0004 Action / capability boundary
- [[10_Sources/Blog/ai-agents-101-tools-in-python|AI Agents 101, Tools in Python]]: puts a timeout on every external call (10 seconds for search, 30 for code execution) and uses is_relative_to path checks as a capability boundary.
- [[10_Sources/Blog/anthropic-how-we-contain-claude|How We Contain Claude]]: argues the deterministic environment boundary holds when probabilistic model defences miss, and that allowlists are capability grants that can become exfiltration paths.
- [[10_Sources/Blog/function-calling-how-llms-use-tools|Function Calling Explained]]: the model only requests a tool call while application code executes it, which fixes where the action gate sits.
- [[10_Sources/Blog/karpathy-agents-md-framework|Karpathy agents.md framework]]: scales autonomy to action reversibility with READ, WRITE, NEVER and HUMAN_CHECKPOINT tiers. Speculative commentary, but a concrete test of the action gate.
- [[10_Sources/Blog/mcp-101-build-your-first-server|MCP 101]]: warns an MCP server runs with the launching process's permissions, so server trust is not a sandboxed capability grant.
- [[10_Sources/Blog/mcp-security-attack-vectors|MCP Security Attack Vectors]]: names six attacks including tool description poisoning and rug pulls, so the gate needs pinned versions, scoped filesystem access and audit.
- [[10_Sources/Blog/webmcp-complete-guide|WebMCP Guide]]: warns tool descriptions are a prompt-injection surface and nothing verifies a tool does what it claims, supporting a gate that distrusts tool metadata.
- [[10_Sources/Books/how-to-design-an-agent-bommarito-2025|How to Design an Agent (Bommarito)]]: proposes risk metadata (reversibility, approval, audit) in the tool manifest so the host enforces controls.
- [[10_Sources/Docs/claude-agent-sdk-overview|Claude Agent SDK overview]]: allowed_tools, hooks, permission modes and subagents form the capability boundary a reference runtime exposes.
- [[30_Concepts/tool-use|Tool Use]]: treats a tool as a contract of name, description and typed schema run by the harness outside the model.

### af:ADR-0005 State, context, memory
- [[10_Sources/Blog/agent-memory-systems-guide|Agent Memory Systems Guide]]: treats context as RAM and memory as disk, and says write quality sets memory quality, so the write path needs a filter.
- [[10_Sources/Blog/agentmemory-fix-memory-loss|agentmemory]]: memory captured by lifecycle hooks, compressed to facts and evicted by decay, with CLAUDE.md kept for stable rules.
- [[10_Sources/Blog/ai-agents-101-memory-across-sessions|AI Agents 101, Memory Across Sessions]]: argues statelessness is deliberate so persistence is the developer's job, with a file-then-vector escalation rule.
- [[10_Sources/Blog/context-engineering-guide|Context Engineering Guide]]: names four context failure modes and four management strategies, and says tool failures should stay visible in context.
- [[10_Sources/Blog/hermes-self-hosted-agent|Hermes Self-Hosted Agent]]: tier one memory loads deterministically each session beside searchable history, and agent-written skills are drafts for human review.
- [[10_Sources/Blog/karpathy-llm-wiki-pattern|Karpathy LLM Wiki Pattern]]: memory as a persistent LLM-maintained store with immutable raw sources, an index and an append-only log.
- [[10_Sources/Blog/rag-vs-long-context-vs-fine-tuning|RAG vs Long Context vs Fine-Tuning]]: stay in context under about 50K tokens, use RAG for large or changing corpora, and treat agentic retrieval as a tool.
- [[10_Sources/Papers/llm-agent-memory-evolution-survey-luo-2026|Memory Evolution Survey (Luo)]]: warns stale records stay close in embedding space and unbounded growth lets errors contaminate the store.
- [[10_Sources/Papers/llm-agent-memory-survey-du-2026|Memory Survey (Du)]]: models memory as a write-manage-read loop and states long context is not memory.
- [[10_Sources/Papers/vizomem-liang-2026|VizoMem]]: memory as retrievable units separate from the context window, with rendering cutting tokens 3 to 4 times.
- [[30_Concepts/anti-patterns-index|Anti-Patterns Index]]: names hidden state outside the transcript as a failure mode, a check on what must be durable.
- [[30_Concepts/memory|Memory]]: splits memory by horizon and by kind (working, episodic, semantic, procedural), evidence for defining memory against context.

### af:ADR-0006 Persistence and recovery

- [[30_Concepts/best-practices-index|Best Practices Index]]: lists checkpointing so a run resumes rather than restarts, a practice to test against the persistence decision.

### af:ADR-0007 Governance and human authority

- [[10_Sources/Blog/karpathy-agents-md-framework|Karpathy agents.md framework]]: gates before irreversible actions, a concrete test of the human approval design. Speculative commentary.
- [[10_Sources/Books/agentic-design-patterns-gulli-2025|Agentic Design Patterns (Gulli)]]: its human-in-the-loop and guardrail patterns are items to test against the governance design.
- [[10_Sources/Books/claude-code-for-the-rest-of-us-munro-2026|Claude Code for the Rest of Us]]: a three-tier permission model (read-only free, bash and edits approved) layered over OS sandboxing.
- [[10_Sources/Books/governing-ai-agents-risk-bommarito-2025|Governing AI Agents (Bommarito)]]: maps oversight mode to consequence and reversibility (HITL, HOTL, HIC) with a tested emergency stop.
- [[10_Sources/Books/how-to-design-an-agent-bommarito-2025|How to Design an Agent (Bommarito)]]: states governance must be designed in, not retrofitted.
- [[30_Concepts/agent-patterns-index|Agent Patterns Index]]: three human-in-the-loop tiers on a reversibility framework.
- [[30_Concepts/best-practices-index|Best Practices Index]]: human review of high-stakes actions as a standing practice.

### af:ADR-0008 Evaluation and evidence
